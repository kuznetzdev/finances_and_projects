# Контроль финансовой правдоподобности и распределений

## Что контролируется в release gate

\`scripts/lib/financial-plausibility.js\` содержит **консервативные правила по конкретным учебным шаблонам**, не «типичные значения по отрасли». Если исходная модель гарантирует положительность или тождество, нарушение блокирует публикацию. Проверяются:

- \`r-current\`: быстрая ликвидность неотрицательна и не превышает текущую.
- \`r-margins\`: при заданных положительных расходах валовая рентабельность не ниже операционной, операционная не ниже чистой; валовая рентабельность не выше 100%.
- \`r-leverage\`: доля долга в источниках финансирования 0–100% и согласована с Debt/Equity.
- \`v-wacc\`: при положительных ставках и весах WACC положителен и не превышает 100%.
- \`v-pi\`: индекс прибыльности неотрицателен при положительных PV и инвестициях.
- \`v-irr-zero\`: IRR для единственного положительного терминального платежа выше −100%.
- \`r-roe-roa\`: положительные прибыль, активы и капитал задают неотрицательные ROA и ROE.

Дополнительно сохраняются ранее внедрённые независимые DCF-формулы, финансовые тождества для других шаблонов и проверки \`NaN\`/\`Infinity\`. **Отрицательные NPV, CFO, FCFF/FCFE, ROE в других сценариях и денежный цикл не считаются ошибками из-за знака.**

Показатели с нетипичными процентами и мультипликаторами генерируют **информационные флаги**, не обязательные ошибки. Превращать наблюдаемый максимум из генераций в отраслевой норматив нельзя.

## Контроль распределений

\`npm run audit:distributions\` генерирует **96 фиксированных seed на каждый из двух поддерживаемых уровней** (если у шаблона только один уровень, один набор). Пишет \`artifacts/generator-distributions.json\` и \`.md\`:

- Число уникальных условий и числовых ответов, доля самого частого варианта.
- Минимум, медиана, 5-й и 95-й процентили по каждому числовому показателю.
- Выбросы по интерквартильному размаху (за пределами 3×IQR); их значения и seed доступны в отчёте.
- Проверка сжатия разнообразия для заранее объявленных высоковариативных шаблонов.

\`npm run audit:distributions:deep\` проверяет **1000 seed на уровень**. Глубокий прогон также выполняется в PR и перед публикацией в GitHub Pages. Расписание отдельного еженедельного глубокого прогона: \`.github/workflows/distribution-audit.yml\`; доступен и ручной запуск через GitHub Actions.

## Политика блокировок

- **Ошибка (красная):** математически невозможный результат в объявленной учебной модели, либо падение уникальности ниже 20% и частота одной комбинации выше 25% в шаблоне с жёстким контрактом разнообразия. В случае нормальных ограниченных дискретных сценариев этот контракт не применяется.
- **Сигнал для разбора:** редкий крайний результат, нетипичный процент, один и тот же вариант при многократной генерации в шаблоне без контракта. Эти события попадают в отчёт, но не блокируют деплой.
- **Не проверяется этим модулем:** правильность каждой формулы для всех 126 шаблонов, соответствие сюжета входным данным во всех задачах и актуальность налогового законодательства. Независимые формулы остаются отдельным слоем качества.

Предварительно заданы пять контрактов высокой вариативности: \`v-pv\`, \`v-fv\`, \`r-current\`, \`a-horizontal\`, \`dcf-two-stage\`. Порог привязан к учебной природе этих шаблонов, а не ко всем 122. Другие шаблоны постепенно включаются после анализа их действительных распределений, чтобы фиксированные сценарии не давали ложные блокировки.

## Тестирование

\`tests/financial-plausibility.test.js\` проверяет реальные генерации и намеренно испорченные показатели. \`tests/generator-distributions.test.js\` доказывает, что заданный высоковариативный шаблон с константным результатом блокируется, но дискретный шаблон не блокируется по той же причине. Наличие флагов распределения не означает наличие арифметической ошибки.

Отчёты доступны среди артефактов PR и GitHub Pages CI. Все seed фиксированы, поэтому аномалию можно воспроизвести.


## Первые результаты и интерпретация

Первые 228 000 генераций показали два типичных источника статистических флагов: прогрессивные ступени НДФЛ (распределение имеет группы, поэтому некоторые суммы формально выходят за 3×IQR) и точку безубыточности (при малой удельной марже появляются большие значения количества изделий). Возврат на собственный капитал ROE выше 100% в задаче DuPont при высоком рычаге также не является автоматической ошибкой.

Наряду с IQR, глубокий аудит теперь выделяет шаблоны с числом уникальных сценариев **не более 2%** от числа генераций. Небольшие конечные наборы вроде фиксированных налоговых ставок или страховых режимов будут предупреждением для проверки, а не автоматическим поводом для блокировки.

Это диагностические данные, а не доказательство ошибки генератора. При подозрительном флаге нужно сверить первичные параметры и финансовую формулу, затем сохранить осмысленное исключение или исправить задачу.

## Контроль известных статистических сигналов (2026-10-30)

По глубокому аудиту 235 000 генераций выявлены 22 диагностических сигнала, не являющихся автоматически доказанными ошибками. Они классифицированы в `scripts/lib/distribution-review.js`: ограниченная учебная сетка цен/налоговых режимов/теоретических примеров; многоступенчатые суммы НДФЛ; чувствительность точки безубыточности к малой марже; ROE выше 100% при высоком рычаге. Короткий аудит дополнительно отмечает крайние значения IRR, DSCR и защитного PUT. Для каждой допускаемой группы задана причина и верхняя граница частоты или нижняя граница разнообразия. **Новый сигнал, увеличение доли выбросов сверх установленной границы или потеря известных сценариев приводит к неуспеху CI**. Диагностика не подавляется: все исходные предупреждения сохраняются в `.json`/`.md` и печатаются в логах. Это не заменяет независимую проверку формул.

После этапа по структуре капитала и налогам независимый пересчёт охватывает 51 из 126 генераторов. Для оставшихся 61 `generic-only` и 14 `separate-numeric-tests` статус математического покрытия не повышается без отдельного эталона. Матрицу формирует `npm run coverage:finance`.
