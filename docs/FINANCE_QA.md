# Независимая проверка финансовых ответов

## Назначение

Общие тесты `preflight` контролируют структуру задач, конечность числовых ответов и часть финансовых тождеств. Это не эквивалент независимой проверки **всех** ответов. Проверочные реализации формул нужны отдельно от расчётов генератора.

## Текущий этап

Для семи шаблонов DCF добавлен `scripts/lib/finance-oracles.js`. Этот модуль рассчитывает **каждый выведенный числовой ответ** по исходным полям `audit` без использования готовых величин `ev`, `tv`, `fcfe` и аналогичных результатов генератора. Появление неизвестного ключа вопроса в этих шаблонах блокирует публикацию.

Ограничение: исходные поля `audit` формируются тем же генератором, что и условия задач. Новый слой защищает от ошибок арифметики и несоответствия `question.answer` исходным параметрам, но **пока не доказывает согласованность текста условия с полями `audit`**. Следующая итерация выделит входные параметры `inputs` и добавит отдельную сверку условий.

## Полная матрица 122 шаблонов

Запустите `npm run coverage:finance`. Скрипт перебирает текущий реестр и создаёт:

- `artifacts/finance-coverage.md`: ID, модуль, тема, сложность, тип контроля, ключи вопросов и поля `audit`.
- `artifacts/finance-coverage.json`: та же информация для автоматизации.

Матрица собирается заново при каждом PR и перед деплоем, поэтому новые шаблоны не пропадают из учёта. Статус `generic-only` или `audit-data-only` **не означает**, что проверена финансовая правильность вычислений. Матрица не выдаёт общие тесты за независимый расчёт.

## Публикация

`npm run preflight` вызывает финансовые оракулы и блокирует публикацию при расхождении. `npm test` дополнительно проверяет воспроизводимые сценарии с разными уровнями и намеренно повреждёнными результатами. Отчёты из `artifacts` сохраняются в GitHub Actions.

## Дальнейшая очередь

1. Разделить исходные параметры `inputs`, вычисления и учебное отображение.
2. Расширить независимый пересчёт на остальные финансовые семейства, особенно `x-`, `capital-`, `tax-`, `v-`, `a-`.
3. Добавить типы финансовых показателей и обоснованные диапазоны (отрицательный NPV/CFO сам по себе допустим).
4. Добавить статистический контроль тысяч `seed` с порогами по шаблонам, включая фиксированные учебные задачи.
5. Закрыть предупреждения о краткости подсказок после проверки их содержания.
