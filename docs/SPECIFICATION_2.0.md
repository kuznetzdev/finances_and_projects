# 1. Назначение документа

**Статус:** проект требований к следующей версии. Это **не описание уже реализованных функций**. Первая версия содержит 20 генераторов, пять разделов, четыре уровня, проверку и локальную статистику. Ниже описана целевая версия 2.0, состав работ и критерии приёмки.

**Продукт:** «ФинПрактика» — бесплатный учебный веб-тренажёр финансов компании и оценки инвестиционных проектов. Работает в браузере на телефоне и компьютере, размещается на GitHub Pages в публичном репозитории. Для основных функций не нужны аккаунт, сервер, платный ИИ и база данных.

**Цель обучения:** научиться быстро и правильно (1) классифицировать финансовые события, (2) понимать причинно-следственные связи между тремя формами отчётности, (3) выполнять расчёты и (4) критически проверять достаточность исходных данных и обоснованность выводов.

**Источники содержания:** лекции МФТИ Е. Васиной № 1 «Учёт и отчётность. P&L», № 2 «ОДДС. Баланс», № 3 «Налогообложение. Финансовое моделирование», примеры задач пользователя по трём формам и шесть примеров аналога контрольной (PV, YTM, WACC, NPV, CFO, налоговый щит). Задачи по финансовой оценке включены по пользовательским примерам, а не выдаются за подробное содержание лекции № 3.

## 1.1. Обязательные принципы

1. **Корректность важнее количества.** Случайными бывают параметры и варианты условий; экономическая модель и алгоритм проверки — детерминированы и тестируются.
2. **Понимание важнее подстановки.** Для каждой формулы обязательны логические проверки: как трактуется операция, чего не хватает, где типичная ошибка.
3. **Сначала ответ — затем разбор.** Решение скрыто до попытки или отдельного осознанного действия «Показать решение».
4. **Короткие циклы обучения.** Упражнение без обязательной регистрации и настройки, тренировка на 3–10 минут, возвращение к ошибкам.
5. **Честные условия.** Налоги, НДС, момент оплаты, соглашения о времени денежных потоков и правила классификации указаны прямо.
6. **Мобильность без потери смысла.** Любая задача решается с клавиатуры, мыши и сенсорного экрана. Перетаскивание никогда не единственный способ ответить.
7. **Нет ложной точности.** Если данных недостаточно, это полноценный правильный ответ с пояснением, каких параметров не хватает.

## 1.2. Границы проекта

**Входит:** задания с генерацией, экспресс-тесты, карточки терминов, повторение ошибок, краткие справки, контрольная на время, статистика, воспроизводимая ссылка на задачу.

**Не входит в базовую бесплатную версию:** общий рейтинг между устройствами, личные кабинеты, проверка свободного эссе ИИ, официальные налоговые консультации, хранение персональных данных, общая синхронизируемая база результатов.

# 2. Навигация и основные пользовательские сценарии

Главная навигация содержит **пять разделов**: «Тренировка», «Быстрый тест», «Карточки», «Контрольная», «Прогресс». Доступ к «Терминам» — из поиска и каждого задания; «Настройки» — через отдельную компактную кнопку. На узком экране верхняя часть не перегружена вкладками, наиболее частые действия доступны в нижней панели.

| Сценарий | Путь пользователя | Результат |
|---|---|---|
| Потренироваться 5 минут | Главная → тема → уровень → задача → ответ → проверка | Следующая задача без возвращения к меню |
| Выучить отличия | Карточки → набор «прибыль / деньги» → вспомнить → перевернуть → оценить знание | Карточка возвращается по расписанию |
| Проверить классификацию | Быстрый тест → 10 операций → распределить по P&L/CFO/CFI/CFF/BS | Разбор каждой неверной классификации |
| Подготовиться к контрольной | Контрольная → 15–20 минут → задачи разных типов → завершить | Балл по темам, решения после завершения |
| Исправить слабые места | Прогресс → «Мои ошибки» → повторить | Персональный набор упражнений |
| Поделиться заданием | Открытая задача → «Скопировать ссылку» | Другой человек видит те же исходные данные |

## 2.1. Макет экранов

**Главная:** краткая панель прогресса, кнопка «Продолжить», три видимых формата практики, список тем с индикатором освоения. Ни регистрации, ни вводного мастера.

**Экран задачи:** тема, уровень, номер, текст условия, при необходимости компактная таблица, вопросы с ответами и единицами измерения, действия «Проверить», «Подсказка», «Пропустить». После проверки — статусы по вопросам, объяснение шаг за шагом, кнопка «Следующая».

**Карточки:** один термин/отличие на экран, действие «Открыть ответ», после ответа оценка «Не помню / С трудом / Знаю», далее следующая. Визуальные эффекты не должны тормозить обучение.

**Прогресс:** успехи по темам, количество решений, повторения на сегодня, ошибки по понятиям и последняя сессия. Статистика хранится локально, поэтому это указывается пользователю.

# 4. Форматы заданий и проверка

| Формат | Действие учащегося | Проверка |
|---|---|---|
| Числовой ответ | Ввести число и единицу измерения | Точное значение с допуском округления |
| Несколько связанных ответов | Заполнить 2–6 финансовых показателей | Проверка каждого поля и промежуточной логики |
| Один правильный вариант | Выбрать понятие или верный вывод | Совпадение с ключом и объяснение каждого отвлечения |
| Несколько правильных | Отметить все корректные утверждения | Сравнение множества, частичный зачёт по правилам режима |
| Классификация операций | Выбрать категорию у каждой строки | Сверка категории по каждой операции |
| Сопоставление | Соединить понятие, формулу и определение | Сверка пар; на телефоне — два последовательных выбора |
| «Что изменится?» | Определить направление: +, −, 0, не определить | Матрица эффектов; числовое поле по необходимости |
| Найди ошибку | Выбрать неверную строку отчёта и корректировку | Набор обязательных исправлений |
| Недостаточно данных | Выбрать «Определить нельзя» и причину | Два этапа: верное решение и верный отсутствующий параметр |
| Сценарий / чувствительность | Изменить ставку, цену, срок, объём | Пересчёт и экономическое объяснение |
| Мини-отчёт | Заполнить P&L/CFS/BS в компактной форме | Формулы, внутренние равенства и логика классификации |
| Карточка с активным вспоминанием | Вспомнить определение до открытия | Самооценка и контрольный вопрос через несколько повторений |

**Особая логика проверки:** текстовые свободные рассуждения без сервера не оцениваются «по смыслу». Вместо ложной автоматической оценки предлагаются структурированные варианты причин, причинно-следственные цепочки и эталонный разбор. Свободное поле комментария — только для самопроверки.

# 5. Банк генераторов: целевая структура

Обозначения: **Ч** — числовой расчёт; **Л** — логика; **К** — классификация; **О** — ошибка/диагностика; **М** — мини-модель. Каждый ID обозначает самостоятельный *механизм*, а не одну неизменную задачу. Генератор меняет числа, период, объект, последовательность событий и, где указано, причинно-следственный вопрос.

## 5.6. H–I: оценка проектов и финансовые показатели

| ID | Шаблон | Проверяемая идея / вариативность |

| HI06 | NPV: календарь денежных потоков (Л) | Перенос оплаты на год меняет стоимость проекта |
| HI07 | NPV и чувствительность к ставке (Л+Ч) | При прочих равных более высокая ставка снижает PV положительных CF |
| HI08 | IRR: определить смысл и ограничения (Л) | IRR как нулевая NPV, неоднозначность при нестандартных потоках |
| HI09 | Ликвидность vs рентабельность (Л) | Прибыльная фирма с недостатком денежных средств |
| HI10 | Current / quick ratio (Ч) | Различие текущей и быстрой ликвидности |
| HI11 | Оборачиваемость запасов / ДЗ (Ч) | Средний остаток и поток за период, дни оборота |
| HI12 | ROS, ROA, ROE (Ч+Л) | Показатель прибыли / корректная база; средние активы и капитал |
| HI13 | EBITDA margin vs net margin (Ч+Л) | Различия прибыли на разных уровнях отчёта |
| HI14 | Денежный цикл CCC (Ч) | DIO + DSO − DPO; роль отсрочки поставщиков |

**Итого каталог целевой версии: 68 механизмов** (12 + 14 + 8 + 12 + 8 + 14). Комбинации параметров, типов вопросов и сценариев создают практически неограниченный набор повторений; слово «бесконечный» означает генерацию без фиксированного списка задач, а не бесконечное число принципиально новых концепций.

# 6. Шесть примеров контрольной: правильные решения и допущения

Все ответы ниже — **контрольные примеры для тестов разработчика**, а не подсказки на экране до попытки пользователя.

| Тема | Эталонный расчёт | Результат |
|---|---|---|
| PV | 1 800/(1+0,09)^4 | **1 275,17 млн ₽** |
| YTM, бескупонная | (2 000/1 600)^(1/4)−1 | **5,74% годовых** |
| WACC | 0,55×20% + 0,45×14%×(1−25%) | **15,725% ≈ 15,73%** |
| NPV | −2 000 + 900/1,10 + 800/1,10² + 900/1,10³ | **+155,52 млн ₽**, проект принять при заданных допущениях |
| CFO | 450 + 90 + 20 − 60 − 15 | **485 млн ₽** |
| Налоговый щит | (6 000/6)×20% | **200 млн ₽ за первый год**, если налоговый вычет используется полностью |

**Условия обязательны:** PV/NPV предполагают годовую ставку и поступление потоков в конце соответствующих лет, кроме инвестиций в момент t=0; YTM — ежегодное сложное начисление и удержание до погашения без дефолта; WACC — веса по рыночной стоимости долга и капитала, если специально не сказано иное, и налоговая вычитаемость процентов; налоговый щит — достаточная налогооблагаемая прибыль либо обоснованный способ использования налогового эффекта. Ставка **20%** в задаче о налоговом щите — условие упражнения, **не действующая базовая ставка налога на прибыль РФ за 2026 год**.

# 7. Быстрые тесты и карточки для запоминания

## 7.1. Не изучать по одной карточке то, что путают попарно

Наборы карточек строятся вокруг *отличий*: «прибыль ↔ денежный поток», «выручка ↔ поступление денег», «затраты ↔ расходы», «CAPEX ↔ OPEX», «актив ↔ расход», «ДЗ ↔ КЗ», «НДС исходящий ↔ входящий», «валовая прибыль ↔ EBIT ↔ EBITDA ↔ NI», «PV ↔ FV ↔ NPV», «стоимость долга ↔ WACC ↔ доходность облигации», «ликвидность ↔ платёжеспособность», «оборачиваемость ↔ рентабельность», «маржа ↔ наценка», «рост капитала ↔ рост остатка денег».

Каждая пара имеет три шага: **объяснить простыми словами → выбрать правильную ситуацию → применить к микрозадаче**. Например, после карточки «амортизация — неденежный расход» пользователь отвечает, что произойдёт с CFO косвенным методом, если амортизация выросла на 2 млн при неизменности остальных факторов.

## 7.2. Форматы коротких квизов

- **10 за 2 минуты:** один термин — один выбор, мгновенный разбор после ответа в учебном режиме.
- **Куда отнести?** 8–12 операций по категориям «P&L / CFO / CFI / CFF / BS / несколько форм»; категория «несколько форм» требует дальнейшего уточнения. Для одноосной классификации заранее выбирается конкретный вопрос («К какому разделу ОДДС относится платёж?»), чтобы избежать двусмысленности.
- **Что изменится?** По каждой операции выбрать влияние на прибыль, деньги, активы, обязательства, капитал.
- **Соедини понятия:** 6 терминов и 6 определений. На мобильном это последовательные касания, а не обязательное перетаскивание.
- **Найди неверный тезис:** среди похожих утверждений один неверный; после ответа объяснить ловушку.
- **Два вопроса подряд:** определение, затем расчёт. Знание засчитывается только при успешном применении.

## 7.3. Примеры быстрых карточек и проверочных вопросов

| Вопрос | Эталон / ключевой смысл |
|---|---|
| Получен аванс, товар не отгружен. Это выручка? | Нет, обычно обязательство по договору; деньги уже поступили |
| Признана выручка, клиент ещё не платил. Что растёт? | Дебиторская задолженность |
| Компания получила кредит. Это прибыль? | Нет, обязательство и финансовый денежный приток |
| Оплачено оборудование. Это текущий расход? | Обычно нет; ОС и CFI, затем амортизация в P&L |
| Почему амортизация прибавляется при расчёте CFO от NI? | Расход уменьшил NI, но сам не был платежом периода |
| Увеличилась ДЗ при том же NI. Что с CFO? | Уменьшится, при прочих равных |
| Увеличилась КЗ при том же NI. Что с CFO? | Увеличится, при прочих равных |
| Дивиденды уменьшают чистую прибыль? | Нет; уменьшают капитал, а при оплате — деньги |
| НДС в сумме с НДС является выручкой? | При обычном учёте облагаемой продажи выручку показывают без НДС |
| Положительная чистая прибыль означает положительный CFO? | Нет, из-за оборотного капитала и других факторов |
| Ликвидность и рентабельность — одно и то же? | Нет: способность быстро превратить актив в деньги против отдачи/прибыли |
| DSO вырос. Это ускорение сбора денег? | Нет, средний срок получения оплаты увеличился |
| WACC вырос при остальных равных. Что с NPV положительных будущих потоков? | Снижается |
| PV — сумма в будущем или сегодня? | Стоимость будущей суммы в выбранный текущий момент |
| YTM бескупонной облигации растёт, когда рыночная цена падает? | Да, при неизменном номинале и сроке |
| NPV положительна. Что показывает вывод? | Проект создаёт стоимость при принятых потоках, ставке и рисках |

## 7.4. Повторение материала

Алгоритм MVP: **три состояния** «не помню / с трудом / знаю», интервалы ориентировочно **1, 3, 7, 14 дней**, корректируемые по качеству ответа. Неправильная карточка возвращается в текущей сессии через несколько других, а также попадает в следующий день. При самооценке «знаю» через 1–2 повтора система всё равно задаёт микропример для проверки знания. Пользователь видит «На сегодня: 8 повторений», без наказаний за пропуски и искусственных серий активности.

# 8. Краткий обязательный словарь

| Термин | Короткое определение и формула (где применимо) |
|---|---|
| Ликвидность актива | Скорость и лёгкость превращения актива в деньги без существенной потери стоимости |
| Ликвидность компании | Способность исполнять краткосрочные платежи; зависит от качества оборотных активов |
| Платёжеспособность | Способность выполнять финансовые обязательства в срок, включая долгосрочные |
| Оборотный капитал (Net Working Capital) | Текущие активы − текущие обязательства; зависит от контекста расчёта |
| Операционный ЧОК | ДЗ + запасы + прочие операционные оборотные активы − КЗ − операционные обязательства; деньги и финансовый долг обычно исключаются |
| Рентабельность | Относительная прибыльность по отношению к выручке, активам, капиталу или затратам |
| Валовая маржа | Валовая прибыль / выручка × 100% |
| Операционная маржа | EBIT / выручка × 100% |
| Чистая маржа (ROS) | Чистая прибыль / выручка × 100%; указать используемую меру прибыли |
| ROA | Чистая прибыль / средние активы × 100% (один из распространённых вариантов) |
| ROE | Чистая прибыль / средний собственный капитал × 100% |
| Current ratio | Оборотные активы / краткосрочные обязательства |
| Quick ratio | (Оборотные активы − запасы − иные неликвидные краткосрочные активы) / краткосрочные обязательства |
| Оборачиваемость запасов | Себестоимость продаж / средние запасы за период |
| DIO | Средние запасы / себестоимость продаж × дней в периоде |
| DSO | Средняя торговая ДЗ / выручка × дней в периоде |
| DPO | Средняя торговая КЗ / закупки × дней в периоде; при упрощении — себестоимость с оговоркой |
| Денежный цикл (CCC) | DIO + DSO − DPO |
| Выручка | Доход от обычной деятельности в момент выполнения обязательства перед клиентом |
| Прибыль | Доходы − расходы за период по начислению, с учётом выбранного уровня отчёта |
| CFO / CFI / CFF | Денежные потоки операционной / инвестиционной / финансовой деятельности |
| CAPEX / OPEX | Капитальные вложения / текущие операционные расходы |
| Амортизация | Распределение амортизируемой стоимости актива на периоды использования |
| EBITDA | EBIT + амортизация ОС и НМА, при сопоставимых определениях |
| EBIT | Прибыль до процентов и налогов, в рамках выбранной схемы P&L |
| PV / FV | Текущая / будущая стоимость денег при заданной ставке и периоде |
| NPV | Сумма дисконтированных денежных потоков проекта, включая инвестицию |
| IRR | Ставка, при которой NPV = 0, при наличии подходящего решения |
| YTM | Доходность облигации к погашению при принятом сценарии купонов/реинвестиций |
| WACC | Средневзвешенная стоимость капитала компании с оговорёнными весами и налогами |
| Налоговый щит | Экономия налога вследствие налогового вычета при выполнении условий его использования |
| ОНА (DTA) | Отложенный налоговый актив по вычитаемым временным разницам или переносимым убыткам при соблюдении критериев признания |

**Правило словаря:** по каждому термину — определение простыми словами, формула, пример, «с чем часто путают», вопрос на закрепление и ссылки на упражнения. Формулы рентабельности снабжать подписью «прибыль за период / средняя база за тот же период»; если знаменатель равен нулю либо отрицателен, автоматическая оценка показателя как обычного процента отключается и показывается предупреждение.

# 9. Четыре уровня сложности и адаптация

| Уровень | Числа | Состав задания | Проверяемое умение |
|---|---|---|---|
| 1. Разминка | Целые, простые проценты, 1–2 года | Одна идея, один вопрос | Вспомнить правило и вычислить |
| 2. Практика | Умеренно дробные, 2–4 года | 2–3 взаимосвязанных вопроса | Связать показатели |
| 3. Контрольная | Смешанные параметры, до 5 лет | Отвлекающие операции, 3–5 ответов | Классифицировать и проверять |
| 4. Эксперт | Нестандартные сценарии и время | Найти допущение, недостаток данных, ошибку | Критическое финансовое мышление |

Настройка сложности делится на **уровень математики**, **уровень логики** и **длину условия**. По умолчанию они растут вместе; расширенная настройка позволяет тренировать сложную финансовую мысль с простыми числами. Это принципиально: усложнение только за счёт неудобной арифметики ухудшает учебную пользу.

**Адаптивный режим:** после 3 ошибок по одной концепции в последних 5 встречах система предлагает короткое объяснение и два простых задания. После двух последовательных успешных ответов возвращает исходный уровень. Пользователь в любой момент вручную задаёт уровень; система не скрывает смену сложности.

**Генератор удобных чисел:** стоимость 100–10 000, суммы кратные 5/10/25/100, сроки 1–8 лет, базовые ставки 5/8/10/12/15/20/25%; на уровнях 3–4 допускаются и другие значения. Значения ограничиваются логикой: оплаченная себестоимость ≤ признанной себестоимости, доли ≤ 100%, отрицательная стоимость запасов не создаётся, сумма долей капитала = 100%, амортизация не превышает амортизируемую базу. Не округлять промежуточные вычисления для создания эталона — только вывод ответа.

# 10. Дизайн: требования для телефонов и компьютеров

## 10.1. Визуальное направление

**Стиль:** спокойный функциональный интерфейс учебного инструмента. Светлая тема по умолчанию, тёмная — по настройке или системной теме. Нейтральный фон, один основной цвет для действий (например, тёмно-синий), зелёный/красный — исключительно для результата и обязательно вместе с текстом или значком. **Без градиентов, иллюстраций для украшения, сложных анимаций и игровых баннеров.** Цифры, условие и поле ответа визуально важнее любого оформления.

**Типографика:** системный шрифт, основной текст минимум 16 px на телефоне; текст условия 16–18 px; заголовки 20–28 px; цифры с табличным выравниванием, понятное разделение тысяч, единица рядом с полем. Величины вида `1 250 млн ₽`, ставки вида `12,5%`, отрицательные потоки вида `−320 млн ₽`.

**Геометрия:** базовый шаг отступов 8 px; отступы 8/16/24/32 px; скругление карточек 10–14 px; разделители вместо теней, когда достаточно. Одна основная кнопка на экран.

## 10.2. Адаптивная компоновка

| Размер окна | Компоновка | Требование |
|---|---|---|
| 320–599 px | Одна колонка, боковые поля 16 px | Никакой горизонтальной прокрутки страницы; поля ответа на всю ширину |
| 600–1023 px | Одна широкая колонка до 720 px | Можно размещать два коротких поля рядом, если читаемо |
| От 1024 px | Основной блок до 920–1080 px | Условие слева и компактная панель вопросов/справки справа только при достаточной ширине |

**Телефон:** основная кнопка «Проверить» доступна внизу экрана, но не закрывает вопросы и не конфликтует с экранной клавиатурой; навигация одной рукой; нажимаемые зоны не меньше 44×44 CSS px; переключение полей через «Далее». Таблицы финансовых показателей преобразуются в вертикальные строки «Название / Год 1 / Год 2» либо раскрывающиеся записи. Крупная таблица показывается как отдельный режим просмотра с чёткой локальной прокруткой и закреплёнными подписями, а не ломает всю страницу.

**Компьютер:** можно использовать Enter для перехода и проверки, Tab для фокуса, стрелки для вариантов; ширина строк ограничена для чтения; на широком экране не растягивать текст на 1600 px. Дополнительная справка остаётся рядом, не вмешиваясь в основную область.

## 10.3. Структура экрана задания

```text
МОБИЛЬНЫЙ ЭКРАН                    КОМПЬЮТЕР (широкий)
┌──────────────────────┐            ┌──────────────────────────────────────────┐

│ Уровень 2     ⋮      │            ├──────────────────────┬───────────────────┤
├──────────────────────┤            │ Условие задачи       │ Ответы            │
│ Условие задачи       │            │                      │ CFO [          ]   │
│ ...                  │            │ Данные и операции   │ ДЗ  [          ]   │
│ [Показать детали]    │            │                      │                   │
├──────────────────────┤            │                      │ [?] Подсказка      │
│ Вопрос 1             │            │                      │                   │
│ [        ] млн ₽     │            │                      │ [ Проверить ]      │
│ Вопрос 2             │            └──────────────────────┴───────────────────┘
│ [        ] млн ₽     │

├──────────────────────┤

```

**Ошибки:** после проверки рядом с полем показывается «Неверно: ожидалось …» только если режим разрешает открывать ответ; иначе подсказка без ответа. Текстовое объяснение ошибки содержит расчёт и причину. Нельзя считать пустое поле математической ошибкой: это отдельный статус «Не отвечено».

**Неоднозначные задачи:** явная кнопка «Недостаточно данных», после неё обязательный вопрос «Чего не хватает?». Иначе человек легко выучит стратегию угадывания.

## 10.4. Доступность, управление и производительность

- Контраст обычного текста — не ниже 4,5:1, крупного текста — не ниже 3:1, явная видимая рамка клавиатурного фокуса; цвет не единственный индикатор результата (ориентир WCAG 2.2 AA).
- Поддержка клавиатуры, чтения с экрана, увеличения текста до 200%, системного `prefers-reduced-motion`.
- Поля ответа имеют подписи (`CFO, млн рублей`), сообщения об ошибках связаны с соответствующими полями, изменения результата объявляются доступными средствами.
- Загрузка без внешних крупных библиотек; приложение должно работать при плохом соединении после загрузки. Офлайн-режим — отдельная задача, а не обещание MVP.
- Сброс статистики требует подтверждения; прогресс не должен теряться при простой перезагрузке вкладки.

# 12. Тестирование и критерии приёмки

## 12.1. Автоматические проверки

1. **Генерация:** для каждого шаблона ≥ 1 000 сидов × 4 уровня, без `NaN`, `Infinity`, деления на ноль, невалидных дат и отрицательных остатков там, где они не допускаются.
2. **Бухгалтерские инварианты:** `A=L+E`, `Cash_end = Cash_begin + CFO + CFI + CFF`, `Equity_end = Equity_begin + NI − dividends + contributions` при заданных условиях.
3. **P&L и оборотный капитал:** `NI = Revenue − expenses − interest − tax` в выбранной схеме; `CFO = NI + noncash adjustments − Δoperating assets + Δoperating liabilities` с явно заданной классификацией.
4. **Дисконтирование:** сумма NPV пересчитывается независимым тестовым алгоритмом; год 0 не дисконтируется; при типичных положительных будущих CF рост ставки не увеличивает PV.
5. **Налоговые сценарии:** VAT inclusive/exclusive, вычет НДС только при заданном праве, налоговый щит при достаточной базе, прогрессивная ставка по пороговым частям, ОНА при подтверждённых условиях.
6. **Детерминированность:** два запуска с одинаковыми `id/seed/version` дают одинаковые входные данные и ответы.
7. **Тесты ошибок:** некорректная классификация, пропуск ответа, ошибочный знак, неверная единица и верный ответ «недостаточно данных» обнаруживаются корректно.
8. **Регрессия:** шесть пользовательских примеров контрольной и исторические задачи из лекций — фиксированные эталоны.

# 14. Правила достоверности и спорные места материалов

- В лекции № 3, стр. 13, встречаются оба порога по взносам — **2 979 000** и **2 759 000 ₽**. Для общей базы **2026 года — 2 979 000 ₽**, а 2 759 000 ₽ относится к **2025 году**. Подтверждение: ФНС России, «Страховые взносы» (https://www.nalog.gov.ru/rn77/yul/str_vznos/).
- В лекции № 3, стр. 2, в примере смешаны даты 2024/2025 и 2020/2021. Генератор обязан использовать один непротиворечивый календарь событий.
- Лекция № 2, стр. 17–18, местами подписывает **чистое изменение денежных средств как FCFF**. Это разные показатели. Для приложения: `ΔCash = CFO+CFI+CFF`; `FCFF` — поток для всех поставщиков капитала, рассчитываемый отдельно с оговорённым составом и процентами.
- Лекция № 3, стр. 16, объясняет ОНА главным образом через убыток. Это **учебное упрощение**: отложенный налоговый актив бывает и по вычитаемым временным разницам; признание не происходит автоматически при любом убытке. В генераторе критерии признания описываются явно.
- Амортизационный налоговый щит зависит от возможности уменьшить налогооблагаемую прибыль. Если компания убыточна и в условиях нет будущей реализации эффекта, нельзя автоматически засчитывать `амортизация × ставка` как немедленную денежную экономию.
- Платежи процентов и полученных дивидендов могут по-разному классифицироваться в зависимости от стандарта и принятой учётной политики. В каждой неоднозначной задаче задаётся применяемый вариант; классификация не считается универсальной.
- НДС 22% и налог на прибыль 25% — базовые ставки РФ в 2026 году согласно ФНС, но часть операций и налогоплательщиков имеют специальные режимы. Проверка актуальности: https://www.nalog.gov.ru/new2026/ и https://www.nalog.gov.ru/rn77/taxation/taxes/profitul/ . Учебные ставки из условий (например 20%) имеют приоритет при решении конкретной задачи.
- В P&L, моделировании и заданиях о CAPEX необходимо явно различать признанные расходы, начисленные обязательства и фактические выплаты.
