# Архитектура ФинПрактики 3.0

## Назначение и границы

Рабочий продукт: статическое обучающее приложение, без серверных зависимостей. Пользователь получает новую задачу по теме и сложности, решает её, видит автоматическую проверку и объяснение, повторяет ошибки. Учебные тесты и словарь используют единый каталог терминов. Конфиденциальные пользовательские данные на сервер не отправляются.

## Слои

```text
site/
  index.html, styles.css, app.js  ← интерфейс, состояния страниц, локальная статистика
  data/
    tax.js                      ← версионируемые нормативные ставки и функции
    knowledge.js                ← понятия и задания-классификаторы
  engine/
    index.js                    ← единый реестр и генератор, проверка типов ответа
    helpers.js                  ← детерминированная случайность, форматирование
    legacy.js                   ← проверенные генераторы первой версии (адаптер)
    templates/
      valuation.js              ← деньги во времени, оценка компаний, инвестиции
      taxes.js                  ← налоговая база, НДС, НДФЛ, взносы
      ratios.js                 ← ликвидность, оборачиваемость, рентабельность
      modeling.js               ← спрос, мощность, сценарии, потребность в деньгах
      reasoning.js              ← классификация, ловушки, неоднозначность данных
  .github/workflows/pages.yml   ← тесты + публикация в GitHub Pages
```

### Путь данных

`Тема + уровень + seed + ID шаблона + налоговая политика` → реестр генераторов → чистая `build()` → объект упражнения с условием, вопросами, готовыми ответами и объяснениями → формирование полей UI → проверка → сохранение статистики в браузере.

**Инвариант:** повторный вызов `generateExercise()` с одинаковыми параметрами возвращает равнозначный объект. Ссылки с `?topic=...&level=...&seed=...&template=...` воспроизводят задачу. ID существующего шаблона нельзя без миграции менять после публикации.

## Контракт шаблона

Новый файл, например `site/engine/templates/my-topic.js`:

```js
import { randomInt, num, exercise } from '../helpers.js';

export const templates = [{
  id: 'example-sales', // глобально уникальный и постоянный ID
  topic: 'model',        // существующий ID темы
  min: 1,               // минимальный уровень сложности
  build(rng, level, { tax }) {
    const volume = randomInt(rng, 100, 300);
    const price = randomInt(rng, 2, 8);
    return exercise(
      this.id,
      this.topic,
      'Выручка по объёму и цене',
      `Продано ${volume} единиц товара по ${price} млн ₽.`,
      [num('revenue', 'Выручка', volume * price)],
      'Перемножь количество товаров и цену.',
      [`Выручка = ${volume} × ${price} = ${volume * price} млн ₽.`],
      'Учебный пример',
      level
    );
  }
}];
```

Затем импортируйте `templates as newTemplates` и добавьте `...newTemplates` в `plugins` в `engine/index.js`. Дальше регистрация и проверка выполняются автоматически. Отдельно напишите тест на финансовые инварианты и пройдите `npm test`.

### Стандарт вопросов

- `number`: `{key, label, type:'number', answer:number, unit, tolerance}`. Допустимы запятая и точка, проверка абсолютного допуска.
- `choice`: `{key, label, type:'choice', answer:string, choices:string[]}`. Один ответ.
- `multi`: `{key, label, type:'multi', answer:string[], choices:string[]}`. Отметить все правильные, порядок не влияет.

Поля каждого упражнения: `id`, `topic`, `title`, `story`, `questions`, `hint`, `explanation`, `source`, `level`. В итоговом ответе движок добавляет `seed`, `templateId`, а в новых шаблонах также `taxPolicy`.

Для новых типов вопросов требуются два расширения: проверка в `checkAnswer()` и доступный элемент ввода в UI. Существующие вопросы не зависят от их появления.

## База знаний

`CONCEPTS` состоит из записей `id, term, definition, group, contrast, source`. Один факт отображается в словаре, карточках и квизе без дублирования. `OPERATIONS` содержит `id, event, answer, why` и используется классификационным квизом. Для нового понятия достаточно добавить запись, для новой операции также достаточно записи.

## Нормативные данные

`policyFor('RU-2026')` возвращает конфигурацию со ставками и ссылками на ФНС. Шаблоны используют `ctx.tax` и явно пишут выбранную ставку в условии. Обновление нормативных данных: создать новую версию по году, подтвердить официальным источником, покрыть тестами, затем назначить её значением по умолчанию. Исторические кейсы с явно заданной 20% ставкой сохраняют эту ставку в условии.

## Миграции и обратная совместимость

- `legacy.js` изолирован от новых модулей; при переносе отдельных старых шаблонов необходимо оставить исходный ID.
- `localStorage` использует ключ `finpraktika.v3`; прежние версии не удаляются без миграции.
- Данные прогресса экспортируются в JSON. Это экспорт, а не автоматическая синхронизация.
- Прежде чем выпускать новую версию: тесты всех шаблонов, численные ограничения, семантическая версия, проверка URL и источников.

## Что намеренно не включено

Сервер, личные кабинеты, генерация задач через LLM, онлайн-база пользователей, редактор преподавателя и публикация новых шаблонов через пользовательский интерфейс. Для независимого развёртывания на GitHub Pages всё это избыточно. Архитектура разрешает добавить их отдельными слоями без переписывания финансового ядра.
