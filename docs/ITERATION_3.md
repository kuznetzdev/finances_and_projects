# Итерация 3. DCF, финансовый pre-flight и формулы

## Объём итерации

Изолированная ветка построена поверх итерации 2. В основной ветке `main` изменений нет. Новые материалы дополняют, но не изменяют 57 исходных кейсов.

### Доступные генераторы
- `dcf-fcff-ebitda-tax`: NOPAT и FCFF на основе EBITDA, амортизации, налогов, CAPEX, ΔNWC.
- `dcf-fcfe-equity`: FCFE, Ke и стоимость собственного капитала при явно описанном потоке.
- `dcf-two-stage`: несколько прогнозных лет и терминальная стоимость Гордона.
- `dcf-terminal-exit`: выход по EV/EBITDA с дисконтированием терминала.
- `dcf-midyear`: различие момента признания потоков (середина и конец года).
- `dcf-sensitivity`: WACC, g и стоимость, анализ чувствительности.
- `dcf-income-capitalization`: капитализация нормализованного FCFF следующего года.

### Банк решений и словарь

B09: две оценки компании (FCFF/WACC и FCFE/Ke) на согласованных предпосылках постоянного безопасного долга, нулевого роста и корпоративного налогового щита. Присутствуют 5 явных лет прогнозных потоков и терминальные стоимости, которые дают тот же результат, что и бессрочная капитализация.

Добавлено пять канонических понятий: двухэтапный DCF, терминальный выход по мультипликатору, середина периода, ставка капитализации и чувствительность оценки. Для каждого добавлена отдельная формула с областью применимости.

### Читаемые финансовые формулы

Формулы в словаре и решениях новых DCF-задач используют семантический HTML: дробные черты, верхние и нижние индексы, верхний и нижний пределы суммы, математические символы. Исходный текст формулы сохранён в `aria-label`; пользователь не теряет доступности при увеличении масштаба и на узких экранах. Длинные формулы прокручиваются внутри собственной панели, не расширяя всю страницу.

## Финансовый pre-flight перед деплоем

Команда `npm run preflight` выполняет **только чтение** учебных данных. Все найденные нарушения пишет в `artifacts/preflight-report.json` и завершается с ненулевым кодом при ошибках. На PR этот отчёт сохраняется как артефакт GitHub Actions. Проверка также включена в `pages.yml` до шага `deploy`: при её падении публикация не выполняется.

Контроль состоит из следующих слоёв:

1. **Каталог:** уникальность идентификаторов, наличие тем и структуры заданий.
2. **Генератор:** каждая тема на минимальной и максимальной сложности для 24 seed-наборов по умолчанию. Проверяются наличие условия и вопросов, тип ответа, конечность числа, ограничение погрешности, корректность вариантов, проверка истинного ответа и воспроизводимость seed.
3. **Правдоподобие:** фатальные невозможные показатели по предметным ограничениям (например, ставка терминального роста не меньше WACC, расходящийся FCFF, несходящийся баланс выплат). Числа из чрезмерно больших диапазонов отклоняются; необычайно высокие процентные ответы и слишком краткие формулировки формируют предупреждения для ручного разбора.
4. **Финансовые инварианты:** отдельные независимые проверки 7 новых DCF-семейств и 11 ранее созданных налоговых и капитальных семейств (налоги, амортизация, ROE, WACC, MM, задолженность, очередность выплат).
5. **Банк решений и словарь:** уникальность кейсов, наличие решений и источников, соответствие числовых контрольных точек и корректность отрисовки формул.
6. **Файлы приложения:** проверка существования локальных ресурсов, связанных в HTML/CSS.
7. **Браузер:** отдельно выполняются Chromium smoke-тесты, включая формулы DCF, мобильный экран, тёмную тему и отсутствие ошибок JavaScript.

### Принцип блокировки

Нарушения формул, недопустимые экономические параметры, некорректный ответ, дубли, ошибки рендеринга и несуществующие локальные ресурсы = **ошибка**, деплой блокируется.

Необычная доходность или короткое условие без достаточных предметных данных = **предупреждение**, требующее дальнейшего анализа. Нельзя автоматически считать отрицательные NPV, CFO или убыток аномалией: в корректной финансовой задаче они допустимы.

### Как добавлять шаблоны дальше

Для нового семейства генератора требуется: (а) зарегистрировать ID и учебную тему; (б) добавить `audit` с исходными величинами, позволяющими независимо восстановить ответы; (в) покрыть экономические тождества тестами; (г) включить новые специфические инварианты в `scripts/lib/preflight.js`; (д) проверить адаптивный вид формулы в Chromium.

Pre-flight не является доказательством того, что все учебные формулировки исторически или юридически верны. Текстовые кейсы и новые нормативные требования требуют проверки источников человеком.

## Запуск

```bash
npm test
npm run preflight
PREFLIGHT_SEEDS=60 npm run preflight
npm run check
```

GitHub Actions проверяет PR через `.github/workflows/pr-check.yml`. При публикации Pages первый job `test` запускает модульные тесты, pre-flight и браузерный smoke; job `deploy` зависит от успешного завершения `test`.
